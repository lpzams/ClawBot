## 1. 先用一句话说明白

**ClawBot 是一个负责指挥大模型做事的小程序。**

大模型很像一个聪明的大脑，但大脑自己不能读取你电脑里的文件，也不能决定哪些操作安全，更不知道什么时候应该停下来。

ClawBot 这个 Harness 就像大脑外面的“身体 + 工作台 + 安全员”：

- 接收用户交代的任务。
- 把任务整理成模型能看懂的消息。
- 听懂模型下一步想做什么。
- 检查这件事是否允许执行。
- 调用真正能做事的工具。
- 把工具结果再告诉模型。
- 在任务完成或达到限制时停止。
- 记录整个过程，方便排错和复盘。

## 2. 用“新员工”来理解

假设你招来一名非常聪明、但刚入职的新员工。

这名员工知识很多，表达能力也很强，但存在几个问题：

- 他不知道公司文件放在哪里。
- 他没有天然权限操作电脑。
- 他可能理解错任务。
- 他可能重复工作，不知道什么时候停。
- 出错后，你需要知道他刚才做过什么。

在这个比喻里：

| 项目概念 | 新员工比喻 |
| --- | --- |
| 大语言模型 | 员工的大脑 |
| Prompt | 你交代的任务 |
| Tool | 文件读取器、计算器等办公工具 |
| Harness | 工作流程、权限制度和操作台 |
| Agent | 能在流程约束下使用工具完成任务的员工 |
| Event log | 员工的工作记录 |
| Eval | 检查任务完成得好不好的考核题 |

所以，ClawBot 不是要重新制造一个大模型。它要解决的是：**怎样让现成的大模型按照可靠、可检查的流程工作。**

## 3. 模型、聊天机器人、Harness、Agent 有什么区别

### 模型

输入一些文字，模型继续生成文字。它是能力来源，但不负责你本地程序的安全和流程。

### 聊天机器人

在模型外面加上聊天输入框、历史消息和输出界面。它主要解决“怎样连续对话”。

### Harness

负责把模型接进真实程序：准备消息、调用模型、执行工具、限制权限、记录事件和控制停止。

### Agent

当模型能根据当前情况选择下一步，并通过 Harness 使用工具反复推进任务时，我们通常把整套运行中的系统叫作 Agent。

当前 ClawBot 已经有最小 Harness，但还不是完整 Agent，因为它只调用模型一次，还不会选择和使用工具。

## 4. 为什么不能只调用一次模型 API

如果任务只是“给我写一句广告词”，一次模型调用可能已经够了。

但如果任务是“读取 README，总结项目并把结果保存下来”，模型需要：

1. 知道有哪些工具可用。
2. 决定先读取哪个文件。
3. 提交读取请求。
4. 等 Harness 检查路径和权限。
5. 得到文件内容。
6. 根据内容生成总结。
7. 如果允许写文件，还要再次经过安全检查。

这已经不是一次问答，而是一个有状态、有循环、有边界的工作过程。Harness 管理的就是这个过程。

## 5. 当前版本到底做了什么

在功能目录执行：

```powershell
python -m clawbot "hello harness"
```

你会看到：

```text
ClawBot received: hello harness
```

默认演示仍然使用 Fake Model，所以不需要密钥；通过 `--provider openai` 时可以切换到真实的 OpenAI-compatible adapter。实际路径如下：

```text
你输入命令
    ↓
clawbot/__main__.py 接收 prompt
    ↓
run_agent 检查 prompt 是否为空
    ↓
run_agent 组装一条 user 消息
    ↓
Fake 或真实 adapter 返回文本
    ↓
__main__.py 把回复打印出来
```

现在逐步看一遍。

### 第一步：命令行收到文字

`clawbot/__main__.py` 使用 Python 自带的 `argparse` 读取 `"hello harness"`。

它像公司的前台：负责接收请求，但不负责真正处理业务。

### 第二步：进入 Harness 核心

CLI 调用：

```python
run_agent(args.prompt, fake_model)
```

这里传入两个东西：

- `args.prompt`：用户说的话。
- `fake_model`：本次要使用的模型函数。

把模型当成参数传入，测试时就能换成另一个可控制的 Fake Model，将来真实运行时也能换成模型 API。

### 第三步：检查输入

`run_agent` 先执行：

```python
if not prompt.strip():
    raise ValueError("prompt cannot be blank")
```

这表示全是空格的输入没有实际意义，不应该浪费一次模型调用。

### 第四步：组装消息

Harness 把普通字符串变成：

```python
{"role": "user", "content": "hello harness"}
```

`role` 表示这句话是谁说的，`content` 表示具体内容。真实模型 API 也采用类似的消息结构。

### 第五步：模型返回回答

默认的 `fake_model` 不会思考，只会返回：

```text
ClawBot received: hello harness
```

它的价值不是聪明，而是稳定。我们可以先证明“传送带”没有接错，再按需换成真实模型。真实模型的 HTTP 细节由 `OpenAICompatibleModel` 单独负责，Harness 不需要改变。

## 6. 为什么先造一个看起来很笨的版本

可以把 Harness 想成一条传送带，把模型想成传送带末端的工人。

如果第一天就接入真实模型，失败可能来自：

- API Key 配错。
- 网络失败。
- 账户限流。
- 模型输出发生变化。
- Harness 自己传错消息。

使用 Fake Model 后，上面前四种干扰全部消失。测试失败时，我们可以集中检查自己的代码。

这不是为了少做功能，而是为了把问题一个一个分开学明白。

## 7. 当前每个文件负责什么

| 文件 | 通俗职责 |
| --- | --- |
| `clawbot/__main__.py` | 前台：接收命令行输入并展示结果 |
| `clawbot/agent.py` | 调度员：检查输入、准备消息、调用模型 |
| `clawbot/models.py` | 翻译员：把通用消息转换成供应商请求 |
| `clawbot/__init__.py` | 门牌：告诉 Python 这是 `clawbot` 包 |
| `tests/test_agent.py` | 检查员：确认消息没传错、空输入会拒绝 |
| `docs/` | 教科书和实验记录 |
| `README.md` | 项目的公开说明和入口 |

一个文件只有一个容易说明的主要职责。当前规模不需要再增加 controller、service、repository 或 factory 等分层。

## 8. 当前已经有和还没有的东西

### 已经有

- 命令行入口。
- 最小消息结构。
- 可替换的模型函数。
- 可复用的 `Harness` 类和 OpenAI-compatible 模型 adapter。
- 空输入检查。
- 不访问网络的自动测试。
- Git 分支、worktree、issue、PR 和公开学习网站。

### 还没有

- 工具调用。
- 多步 Agent loop。
- 对话记忆。
- 权限确认。
- 事件日志和评测。

这些不是漏做，而是后面的学习阶段。每加入一个能力，我们都会先说明它解决什么真实问题。

## 9. 以后完整的一次任务会怎样运行

未来用户输入“读取 README 并总结”时，过程会变成：

```text
用户提出任务
    ↓
Harness 把任务交给模型
    ↓
模型提出：我想调用 read_file("README.md")
    ↓
Harness 检查：工具是否允许？路径是否在项目内？
    ↓
read_file 返回文件内容
    ↓
Harness 把结果交还模型
    ↓
模型生成最终总结
    ↓
Harness 输出答案并记录每一步
```

你之后写的工具、循环、安全检查和日志，都会放进这条路径中，而不是互不相关地堆功能。

## 10. 面试时怎样介绍 ClawBot

### 30 秒版本

> ClawBot 是我从零实现的轻量 AI Agent Harness。它不依赖大型 Agent 框架，我用它学习并展示消息编排、模型适配、工具循环、安全边界、事件记录和评测。项目按小步 PR 开发，每个阶段都有测试和公开学习文档。

### 面试官继续追问时

可以沿着一条真实请求来讲：输入怎样进入 CLI、怎样变成消息、模型怎样请求工具、Harness 怎样校验和执行、怎样停止与记录。

不要只背模块名称。能讲清数据怎样走，比画很多框更有说服力。

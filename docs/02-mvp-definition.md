## 1. 一句话定义

ClawBot 是一个可测试、可观察、有安全停止条件的命令行 AI Agent Harness。

## 2. 第一位用户

第一位用户就是项目作者。目标不是服务大量用户，而是完整理解并展示一次 Agent 运行是怎样被编排的。

## 3. 最小演示

最终的核心演示应类似：

```powershell
clawbot "读取当前项目的 README 并总结"
```

运行过程：

1. CLI 接收问题。
2. Harness 建立消息和运行状态。
3. 模型决定直接回答或请求工具。
4. Harness 校验请求，只允许读取项目范围内的文本文件。
5. 工具结果返回给模型。
6. Harness 输出最终回答，并记录每一步事件。

## 4. MVP 必须具备

- CLI 输入与输出
- 清晰的消息表示
- 一个模型接口，以及 Fake Model 和真实模型实现
- 一个受限、无写入能力的工具
- 有最大步数的 Agent loop
- 工具参数校验和项目目录边界
- 不泄露秘密的结构化事件记录
- 不访问网络的核心测试
- 一条端到端演示命令

## 5. MVP 不包含

- Web 或桌面界面
- 用户账户和数据库
- 长期记忆
- 向量数据库与 RAG
- 多 Agent 协作
- 任意 Shell 执行
- 插件市场
- 自定义工作流 DSL

## 6. 完成标准

只有同时满足以下条件，MVP 才算完成：

1. 新环境按照 README 可以运行。
2. 无 API Key 时，Fake Model 演示和测试都能运行。
3. 有 API Key 时，可以切换到真实模型。
4. 非法工具参数、越界文件路径和超步数都会被拒绝或安全停止。
5. 每个关键状态转换都能从事件记录中看见。
6. 自动测试覆盖一次直接回答、一次工具调用和一次安全拒绝。
7. GitHub PR 的自动检查通过。

## 7. 最小模块边界（暂定）

```text
CLI -> Agent loop -> Model
          |
          +-------> Tool
          |
          +-------> Event sink
```

这是数据流边界，不代表现在就要为每个框画抽象类。Phase 1 只在测试或第二个实现确实需要替换点时，才引入最小协议。

## 8. 面试时可以讲的核心权衡

- 为什么先写 Fake Model：让编排测试确定、快速、免费。
- 为什么不用大型 Agent 框架：学习并展示底层循环，而不是隐藏它。
- 为什么先做只读工具：工具调用是最危险的信任边界，先降低破坏面。
- 为什么需要最大步数：模型可能重复调用工具，Harness 必须保证终止。
- 为什么日志与最终回答分开：面向用户的输出和面向调试的证据用途不同。

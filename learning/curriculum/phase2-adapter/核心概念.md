# Phase 2: 适配器模式与模型抽象 - 核心概念

## 学习目标

理解适配器模式如何解耦 Harness 与具体模型供应商，掌握可复用框架设计，学习环境变量管理和错误边界。

## 核心概念

### 1. 为什么需要适配器？

**问题场景：**

如果直接在 Harness 中调用 OpenAI：
```python
class Harness:
    def run(self, prompt):
        # ❌ 硬编码了 OpenAI
        response = openai.ChatCompletion.create(
            model="gpt-4",
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content
```

**问题：**
1. 🔒 **绑定供应商** - 换 Claude 要改 Harness 代码
2. 🧪 **无法测试** - Harness 测试必须调用真实 API
3. 📦 **依赖膨胀** - 所有项目都必须安装 `openai` 包
4. 🔑 **密钥散落** - API key 可能在多处硬编码

### 2. 适配器模式解决方案

**核心思想：** 在 Harness 和具体供应商之间加一层适配器

```
┌─────────────┐
│   Harness   │ 只知道: messages -> string
└──────┬──────┘
       │
       ├─────→ FakeModel (测试)
       ├─────→ OpenAICompatibleModel (生产)
       ├─────→ ClaudeModel (未来)
       └─────→ LocalLLamaModel (未来)
```

**Harness 的视角：**
```python
class Harness:
    def __init__(self, model: Callable):
        self.model = model  # 不关心是什么，只要可调用
        
    def run(self, prompt):
        messages = self._build_messages(prompt)
        return self.model(messages)  # 统一协议
```

**适配器的职责：**
```python
class OpenAICompatibleModel:
    def __call__(self, messages: List[Message]) -> str:
        # 1. 把通用消息转成供应商格式
        # 2. 发送 HTTP 请求
        # 3. 解析响应
        # 4. 返回纯文本
        pass
```

### 3. 适配器的实现细节

#### 3.1 从环境变量读取配置

**为什么用环境变量？**
- ✅ 密钥不进入代码仓库
- ✅ 不同环境（开发/测试/生产）用不同配置
- ✅ CI/CD 容易注入

**实现：**
```python
@classmethod
def from_env(cls, environ=None):
    values = os.environ if environ is None else environ
    api_key = values.get("OPENAI_API_KEY", "")
    if not api_key:
        raise ValueError("OPENAI_API_KEY is required")
    
    return cls(
        api_key,
        model=values.get("OPENAI_MODEL", "gpt-4o-mini"),
        base_url=values.get("OPENAI_BASE_URL", "https://api.openai.com/v1")
    )
```

**使用：**
```powershell
$env:OPENAI_API_KEY = "sk-..."
python -m clawbot --provider openai "hello"
```

#### 3.2 协议转换

**通用消息格式（Harness 使用）：**
```python
messages = [
    {"role": "system", "content": "你是助手"},
    {"role": "user", "content": "hello"}
]
```

**OpenAI API 请求：**
```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "system", "content": "你是助手"},
    {"role": "user", "content": "hello"}
  ]
}
```

**适配器的工作：**
```python
def __call__(self, messages):
    # 1. 构造请求
    payload = {
        "model": self.model,
        "messages": messages  # 格式刚好兼容
    }
    
    # 2. 发送 HTTP
    response = self._send_request(payload)
    
    # 3. 提取文本
    return response["choices"][0]["message"]["content"]
```

#### 3.3 错误处理边界

**网络错误：**
```python
try:
    response = urlopen(request, timeout=self.timeout)
except HTTPError as e:
    raise ModelError(f"HTTP {e.code}") from e
except OSError:
    raise ModelError("provider unavailable") from e
```

**响应解析错误：**
```python
try:
    data = json.loads(response.read())
    return data["choices"][0]["message"]["content"]
except (KeyError, IndexError, ValueError):
    raise ModelError("invalid response format") from e
```

**为什么这样设计？**
- 把所有供应商错误统一成 `ModelError`
- 调用方不需要处理 `HTTPError`, `JSONDecodeError` 等细节
- 错误信息不泄露 API key

### 4. 可复用框架设计

#### 4.1 三层架构

```
┌─────────────────────────────────────┐
│  业务层 (CLI / Web / Job)           │
│  - 收集输入                          │
│  - 选择配置                          │
│  - 展示结果                          │
└─────────────┬───────────────────────┘
              │
┌─────────────▼───────────────────────┐
│  框架层 (clawbot.Harness)           │
│  - 校验输入                          │
│  - 组装消息                          │
│  - 调用模型                          │
└─────────────┬───────────────────────┘
              │
┌─────────────▼───────────────────────┐
│  适配器层 (models.*)                │
│  - FakeModel (测试)                 │
│  - OpenAICompatibleModel (生产)    │
│  - 其他供应商 (未来)                 │
└─────────────────────────────────────┘
```

#### 4.2 跨项目复用

**安装：**
```powershell
cd ClawBot
python -m pip install -e .
```

**在其他项目中使用：**
```python
# other_project/main.py
from clawbot import Harness, OpenAICompatibleModel

def analyze_code(code: str) -> str:
    model = OpenAICompatibleModel.from_env()
    harness = Harness(
        model, 
        system_prompt="你是严格的代码审查员"
    )
    return harness.run(f"审查这段代码：\n{code}")
```

**好处：**
- 其他项目不需要重写消息编排逻辑
- 不需要重写模型抽象
- 不需要重写测试基础设施

### 5. 依赖方向与可测试性

#### 5.1 依赖方向

```
业务代码 ──depends on──> Harness ──depends on──> Model 协议
                                                    ▲
                                                    │
                                    ┌───────────────┴───────────────┐
                                    │                               │
                              FakeModel                    OpenAICompatibleModel
                            (无外部依赖)                    (只依赖标准库)
```

**关键：** 依赖方向是向内的，核心不依赖外部

#### 5.2 测试策略

**单元测试（Harness 逻辑）：**
```python
def test_harness_assembles_messages():
    seen = []
    def spy_model(messages):
        seen.extend(messages)
        return "ok"
    
    harness = Harness(spy_model, system_prompt="test")
    harness.run("hello")
    
    assert seen[0] == {"role": "system", "content": "test"}
    assert seen[1] == {"role": "user", "content": "hello"}
```

**适配器测试（网络协议）：**
```python
def test_adapter_constructs_request():
    def fake_opener(request, timeout):
        # 检查请求格式
```

## 关键设计决策

### 为什么用 urllib 而不是 requests？

**决策：** 只用标准库 `urllib`

**原因：**
1. **零运行时依赖** - 其他项目接入 ClawBot 不需要额外安装包
2. **当前足够** - 只需要发 POST 请求，urllib 可以做到
3. **依赖最小化** - 框架应该尽可能轻量

**未来可能改：**
- 如果需要连接池 → 可以引入 `requests`
- 如果需要 HTTP/2 → 可以引入 `httpx`
- 但会作为可选依赖，不强制安装

### 为什么 opener 可以注入？

```python
def __init__(self, api_key, *, opener: Callable = urlopen):
    self._opener = opener
```

**原因：**
1. **测试友好** - 测试时注入假的 opener，不发真实请求
2. **未来可扩展** - 可以注入带重试、缓存的 opener
3. **依赖注入一致性** - 整个项目都用这个模式

### 为什么有单独的 ModelError？

**不这样做：**
```python
def __call__(self, messages):
    response = urlopen(request)  # 可能抛 HTTPError, OSError...
    return parse(response)        # 可能抛 KeyError, JSONDecodeError...
```

**调用方需要处理：**
```python
try:
    result = model(messages)
except (HTTPError, OSError, KeyError, JSONDecodeError, ...):
    # 太多异常类型
```

**用 ModelError：**
```python
try:
    result = model(messages)
except ModelError as e:
    # 统一处理
```

**好处：**
- 调用方只需要捕获一种异常
- 异常边界清晰
- 内部实现改变不影响调用方

## 企业实践对比

### Uber Michelangelo 平台

**相似点：**
- ClawBot 的 Model 协议 ↔ Uber 的 Model Service 抽象
- ClawBot 的 Fake Model ↔ Uber 的 Mock Prediction Service
- ClawBot 的适配器 ↔ Uber 的 Model Type Adapter

**Uber 的规模：**
- 支持 TensorFlow, XGBoost, PyTorch 等多种模型
- 统一的预测 API：`predict(features) -> predictions`
- 测试时用 Mock Service，生产时路由到真实模型

### AWS SageMaker

**相似点：**
- 统一的 `invoke_endpoint(body)` 接口
- 不同模型类型通过适配器接入
- 环境变量管理凭据
